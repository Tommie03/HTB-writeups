Dog

HackTheBox Writeup

Box Name: Dog

Difficulty: Easy

OS: Linux

Date Completed: 29-10-2026

IP Address: 10.129.231.223

Summary

Enumerating the box showed two ports being open. Port 80 was running Backdrop CMS and, more importantly, an exposed .git repository was leaking the site's source. Dumping the repo and searching through the code gave me a MySQL password. After enumerating valid usernames on the CMS, I reused this password to log in as tiffany. From the admin panel I abused an authenticated RCE in Backdrop CMS 1.27.1 to upload a malicious module and drop a webshell. Enumerating local users gave me johncusack, and reusing the same MySQL password over SSH got me the User Flag. Escalating privileges required checking sudo -l, which showed I could run the Backdrop CLI tool bee as root. Abusing its eval command to execute PHP let me spawn a root shell and grab the Root Flag.

HTTP Enumeration

After adding the hostname to my hosts file I can visit the website on port 80.

echo "10.129.231.223 dog.htb" | sudo tee -a /etc/hosts

The site is a Backdrop CMS instance sitting in maintenance mode. The far more interesting finding from nmap is the exposed .git/ directory, which means the full repository is downloadable and we can read the source offline.

Dumping the repo

git-dumper http://dog.htb/.git/ ./dog-git
cd ./dog-git
grep -riE "password|passwd|pwd|db_|mysql" .

This recovered a MySQL password from the Backdrop configuration in the source. Password reuse was the obvious next step, but I needed a valid user to pair it with first, so I enumerated usernames.

Initial Foothold

Vulnerability Discovery

Backdrop CMS version 1.27.1 is vulnerable to an authenticated remote code execution flaw. An admin-privileged user can upload a crafted module archive, which Backdrop extracts and serves, dropping a PHP webshell under the web root. This means that if I can get into the admin panel, I can get command execution.

CVE: Backdrop CMS authenticated RCE (1.27.1)

Exploitation

First, password reuse. The MySQL password recovered from the .git dump also works for the Backdrop account tiffany, which lands an authenticated admin session.

With admin access confirmed, I used the following PoC to automate the module-upload RCE and drop a webshell. PoC: https://github.com/rvzsec/backdrop-rce

python exploit.py http://dog.htb tiffany <REDACTED>
[>] logging in as user: 'tiffany'
[>] login successful
[>] enabling maintenance mode
[>] payload archive: /tmp/bd_bca02alh/rvzef390c.tgz
[>] batch id = 13; sending authorize 'do_nojs' and 'do'
[>] waiting for shell at: http://dog.htb/modules/rvzef390c/shell.php
[>] shell is live

The PoC labels its prompt root@dog.htb >, but that's cosmetic — the webshell actually runs as the web server user (www-data). From here I enumerated which local accounts have a real login shell.

Privilege Escalation

Enumeration

Checking what johncusack is allowed to run with sudo gave a clear path.

johncusack@dog:~$ sudo -l
User johncusack may run the following commands on dog:
    (ALL : ALL) /usr/local/bin/bee

johncusack can run bee — the Backdrop CMS command-line tool — as any user including root, with no restriction on the command's arguments. The eval subcommand stands out: it will "Evaluate (run/execute) arbitrary PHP code after bootstrapping Backdrop." Arbitrary PHP as root is a trivial path to a shell.

Exploitation and root flag

Using bee eval to run PHP's system() and spawn bash gives a root shell, and I can read the Root Flag.

sudo /usr/local/bin/bee eval 'system("bash")'
root@dog:/var/www/html#

root@dog:~# cat root.txt
<REDACTED>
📷 Save screenshot here as dog_05.png
Root shell via bee eval and the root flag

Gotcha: bee eval has to bootstrap a working Backdrop installation before it will run any PHP. Run it from a random directory and it errors out because it can't locate the Backdrop root. Running it from inside the docroot (/var/www/html) fixes this. Alternatively, point bee at the install explicitly so it works from anywhere:

sudo /usr/local/bin/bee --root=/var/www/html eval 'system("bash")'

Key Takeaways

  • Exposing a .git directory on a production web server leaks the entire source tree and any secrets committed to it — this single misconfiguration seeded the whole compromise.
  • Secrets like database passwords should never be committed to source control, and never reused across the database, CMS accounts, and system users. Here one password unlocked the CMS admin, the webshell, and the SSH user.
  • Keeping software patched matters — Backdrop CMS 1.27.1 was vulnerable to an authenticated RCE, and admin-level module install is effectively equivalent to code execution.
  • Scoping sudo tightly is critical: granting bee (which includes eval) as root is the same as handing out a root shell.
