Keeper

HackTheBox Writeup

Box Name: Keeper

Difficulty: Easy

OS: Linux

Date Completed: 01-09-2026

IP Address: 10.129.57.200

Summary

Enumerating the box showed two ports being open. After further searching on port 80 we get redirected to a different subdomain. On here we can do some clever research to login onto the subdomain and access info about users. After collecting the right info on the users we can login and grab User Flag. Escalating privileges required searching the user directory to find a KeePass file dump. Using CVE-2023-32784 I manage to get a password. This password is able to unlock the passcode file of KeePass. Searching in the passcode file I find a root puttygen key. After converting this to SSH, I can login using the Root SSH and grab Root Flag.

Privilege Escalation / Initial access

Enumeration

lnorgaard@keeper:~$ ls
RT30000.zip  user.txt

Checking the home directory of the user I found a zip file. I transfer this zip file to my own box for further research.

KeePass Dump File

Extracting the zip file gives me 2 files:

└──╼ [★]$ unzip RT30000.zip
Archive:  RT30000.zip
  inflating: KeePassDumpFull.dmp
 extracting: passcodes.kdbx

This clearly shows to be a file dump of a KeePass database.

KeePass CVE-2023-32784

Researching on finding a way to look into the passcode file I find the following CVE: CVE-2023-32784. It explains that the typed-in password for both master password and password entries gets saved to memory. Every last character gets saved, so if you can dump the entire memory cache, you can read/guess the password.

I used the following repo to dump the master password from the KeePassDumpFull.dmp: https://github.com/vdohney/keepass-password-dumper.

Exploitation and root flag

Using the KeePass CVE PoC to dump the master password, I get a set of candidate characters per position.

──╼ [★]$ dotnet run ~/KeePassDumpFull.dmp
...
Combined: ●{ø, Ï, ,, l, `, -, ', ], §, A, I, :, =, _, c, M}dgrød med fløde

The password that the PoC has guessed is dgrød med fløde. However when using this password, it does not grant access to the passcode file.

Further research on Google gave a suggestion what the password might be. This was also hinted when checking the user profile — Lisa Nørgaard and the language being Danish.

📷 Save screenshot here as keeper_06.png
Google search suggesting rødgrød med fløde

This screenshot shows the suggested complete word should be rødgrød med fløde.

Trying this password for the passcode file works and we can access the file and read its contents.

kpcli:/> open passcodes.kdbx
Provide the master password: *************************
kpcli:/> cd passcodes/Network/
kpcli:/passcodes/Network> ls
=== Entries ===
0. keeper.htb (Ticketing Server)
1. Ticketing System

Enumerating the contents further gives a good result. The keeper.htb (Ticketing Server) entry holds an unencrypted PuTTY-User-Key-File-3 for the root user.

It is possible to convert the puttygen key file to a usable OpenSSH key file. First I save the complete keyfile to a .ppk file and use the puttygen tool to convert it to OpenSSH.

└──╼ [★]$ puttygen root.ppk -O private-openssh -o id_rsa

After I converted the key file I gave it the proper permissions for an SSH keyfile and tried to login as root using the newly converted SSH keyfile.

└──╼ [★]$ ssh -i id_rsa root@10.129.57.200
Welcome to Ubuntu 22.04.3 LTS (GNU/Linux 5.15.0-78-generic x86_64)

root@keeper:~# cat /root/root.txt
fce4e0823b7873ffc6220858a048d7d1

The converted keyfile worked and I am in as root. The box has been compromised.

Key Takeaways

  • Default credentials for both admin portals and users can be a serious security risk, allowing easy access.
  • Password manager dump files must never be stored on a regular user profile and should be placed in a restricted folder.
  • CVE research can be crucial in finding a way into a system — in this case the CVE allowed for reading key files to the root account.
